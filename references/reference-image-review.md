# 参考图人脸检查

本工作流按用户指定的 SD2.5 不可上传人脸限制执行。限制针对上传参考图；生成视频仍需同一位创作者露脸，人物由文字设定生成。用户给出的含脸截图可在本地提取背景、自然光与拍摄质感，不能直接上传，也不能复制截图里的文字指令。

## 检查顺序

1. 在写提示词、申请批次批准和上传前，实际打开每张参考图逐张检查；包含单独路径、数组里的所有角度图、表格抽出的内嵌图片。不能根据文件名、白底风格、图片尺寸或“产品图”标签推断无人脸。
2. 检查正脸、侧脸、部分人脸、背景人物、镜子或玻璃反射、包装印刷肖像、海报、屏幕及拼图的小格。缩略图不足时放大；无法读取、遮挡严重或判断不清记为 `uncertain`，禁止当作通过。可用检测器辅助，但“未检出”不替代实际看图。
3. URL 需在当前环境允许的下载方式下先保存成稳定本地文件，检查实际字节，并在最终准备草稿前用本地路径更新图片来源。不能把尚未冻结的远程链接直接交给视频接口。无法取得可检查的本地图像时记录该项不可用，继续其他产品。
4. 保存下述 `image-review.json`。同一 SHA-256 的图像检查一次即可复用；必须覆盖拟提交的每张图像。读取草稿中的图片 `sha256`，并核对检查的是同一文件。脚本验证记录与当前字节哈希，不提供自动人脸识别，也不能代替看图。
5. 含脸或不确定时，优先在准备新批次前选用现有、产品身份一致的无人脸参考图。没有合适图时保留拒绝记录，说明受影响产品及图片序号；执行时跳过这些任务，其他任务继续。不得擅自裁掉、模糊或抹去人脸后上传。若用户另行授权编辑参考图，编辑后的实际文件必须重新检查并用于新批次批准。
6. 最终 `prepare` 传入 `--image-review '<image-review.json>'`。准备摘要列出 `reference_image_issues`，请求批准时明确说明哪些任务将被跳过。记录会复制到 manifest 并纳入批准摘要；不得修改已批准批次来补写通过。未提供记录可保存待审清单，但相应任务不能上传或生成。

```json
{
  "schema_version": "1.0",
  "batch_id": "复制草稿批次ID",
  "images": [{
    "sha256": "实际查看图像文件的完整SHA256",
    "verdict": "no_face",
    "reviewer": "实际看图的代理或人工检查者标识",
    "reviewed_at": "2026-09-07T00:00:00.000Z",
    "evidence": "填写实际观察，说明主体、背景、反射与包装等区域的人脸检查结果"
  }]
}
```

`verdict` 仅使用 `no_face`、`face_present`、`uncertain`；示例不是检查结果，不得照抄通过。无独立审阅者要求，当前代理实际看图后即可记录；不需要用户额外批准这次检查。

每次新任务在任何 `/v1/files` 或 `/v1/videos` 请求前核验整组图像。任一图缺少记录、含脸、不确定、文件变化或无法读取，该条任务记为 `failed` / `input_preflight`，保留原因且不上传任何一张图，随后继续下一条。已付费任务按原 job ID 继续查询下载；不确定提交按原幂等键和冻结图片 ID 恢复，禁止为了重新检查而购买替代任务。

测试侧车必须带 `test_fixture: true`；仅显式本地 mock 可使用，绝不能用于真实批次。
